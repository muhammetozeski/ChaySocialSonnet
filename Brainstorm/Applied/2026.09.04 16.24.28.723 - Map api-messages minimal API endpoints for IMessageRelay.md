# Map /api/messages/* minimal API endpoints for IMessageRelay

Kategori: dm | Efor: M | Rank: 12

## Ne
Add ChaySocialSonnet.Web/Backend/MessagesEndpoints.cs mirroring the existing MapIdentityEndpoints pattern in IdentityEndpoints.cs: POST /api/messages/send (recipientPublicId, encapsulatedKeyBase64, ciphertextBase64) calling the injected IMessageRelay.SendAsync, and GET /api/messages/inbox/{publicId} calling IMessageRelay.GetInboxAsync, returning EncryptedMessage as base64 DTOs. Add SendMessageRequest/EncryptedMessageResponse records to a new MainProject/Backend/MessagesApiContracts.cs (same split IdentityApiContracts.cs uses), wire app.MapMessagesEndpoints() into ChaySocialSonnet.Web/Program.cs next to the existing app.MapIdentityEndpoints() line, and add a MessagesApiClient mirroring IdentityApiClient.cs's HttpClient usage.

## Neden
Verified in code: LocalMessageRelay and IMessageRelay (SendAsync/GetInboxAsync) are fully implemented and unit-tested (MainProject.Tests/Backend/LocalMessageRelayTests.cs), and Program.cs registers IMessageRelay in DI, but only calls app.MapIdentityEndpoints() — there is no app.MapMessagesEndpoints() call and no MessagesEndpoints.cs file at all. So no client on any platform has any HTTP path to the relay yet; this is the concrete, already-tested backend piece with zero external connectivity, and the single blocking gap before any DM feature can work end to end.
