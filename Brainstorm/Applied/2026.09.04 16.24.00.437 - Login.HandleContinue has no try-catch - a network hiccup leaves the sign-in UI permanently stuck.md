# Login.HandleContinue has no try/catch — a network hiccup leaves the sign-in UI permanently stuck

Kategori: protection | Efor: S | Rank: 12

## Ne
MainProject/UI/Pages/Login.razor HandleContinue() (lines 68-86) awaits ApiClient.RegisterAsync then ApiClient.SignInAsync with nothing catching exceptions. Both methods in MainProject/Services/Identity/IdentityApiClient.cs call response.EnsureSuccessStatusCode(), which throws HttpRequestException on any non-2xx response — including the 409 Conflict IdentityEndpoints.cs returns for "This identity is already registered with a different key", or any transient network failure. Wrap the two awaits in try/catch, reset _isSigningIn=false and set _errorMessage on failure. Also give the HttpClient built in ChaySocialSonnet.Web.Client/Program.cs line 14 (`new HttpClient { BaseAddress = ... }`) an explicit Timeout — it currently uses the 100s default, so a hung server leaves the spinner running for a very long time with no feedback either way.

## Neden
Verified directly: neither Login.razor's HandleContinue nor IdentityApiClient has any exception handling, and the HttpClient has no Timeout override. Any server error, a 409 identity conflict, or a network blip during sign-in currently throws inside a Blazor event handler with nothing catching it — _isSigningIn never resets, no _errorMessage is shown, and the Continue button is dead until the user manually reloads the page. This breaks the app's one and only sign-in path for any legitimate transient failure, not just adversarial input.
