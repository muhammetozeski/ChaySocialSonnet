# Wire up PageBase.RequireAuth to an actual navigation guard

Kategori: architecture | Efor: S | Rank: 10

## Ne
In MainProject/UI/Architecture/PageBase.razor.cs, add the actual check inside OnInitialized(): if (RequireAuth && AuthService.CurrentIdentity is null) NavManager.NavigateTo("/login", true); (AuthService is static, so just a using, no injection needed). Then in MainProject/UI/Pages/Profile.razor, override OnInitialized() to set RequireAuth = true before calling base.OnInitialized(), so the parameter is actually exercised.

## Neden
Verified by reading the code: PageBase.razor.cs defines [Parameter] public bool RequireAuth but OnInitialized() only wires up the LocationChanged handler - it never reads RequireAuth. A grep across MainProject confirms RequireAuth and CurrentIdentity are checked nowhere else in the codebase. Profile.razor never sets RequireAuth and displays AuthService.CurrentIdentity?.PublicId directly, so hitting /profile without having signed in renders a blank identity instead of redirecting - a real, currently-open gap in the identity system that already shipped, not a hypothetical.
