# Shared SendAsync helpers on AuthorizedRequests instead of repeating build+send+EnsureSuccessStatusCode in every ApiClient

Kategori: architecture | Efor: S | Rank: 30

## Ne
MainProject/Services/AuthorizedRequests.cs currently only exposes `Create(method, url, jsonBody)`. Every mutating client method then repeats the same 3-4 lines: build the request, `await httpClient.SendAsync(request)`, `response.EnsureSuccessStatusCode()`, and optionally `await response.Content.ReadFromJsonAsync<T>()`. This exact shape appears in FollowApiClient.FollowAsync/UnfollowAsync, SafetyApiClient.BlockAsync/UnblockAsync/SubmitReportAsync, NotificationsApiClient.MarkAllReadAsync, and PostApiClient.CreatePostAsync/DeletePostAsync/ToggleLikeAsync/AddCommentAsync (10 call sites in MainProject/Services/*.cs). Add two overloads next to Create: `public static async Task SendAsync(HttpClient httpClient, HttpMethod method, string url, object? jsonBody = null) { var response = await httpClient.SendAsync(Create(method, url, jsonBody)); response.EnsureSuccessStatusCode(); }` and `public static async Task<T> SendAsync<T>(HttpClient httpClient, HttpMethod method, string url, object? jsonBody = null) { var response = await httpClient.SendAsync(Create(method, url, jsonBody)); response.EnsureSuccessStatusCode(); return (await response.Content.ReadFromJsonAsync<T>())!; }`. FollowApiClient.FollowAsync then becomes one line: `public Task<FollowStatusResponse> FollowAsync(string targetPublicId) => AuthorizedRequests.SendAsync<FollowStatusResponse>(httpClient, HttpMethod.Post, $"/api/follow/{Uri.EscapeDataString(targetPublicId)}");` and similarly for the other 9 call sites.

## Neden
Shrinks 10 near-identical multi-line methods down to one-liners and gives every authorized call the same error-handling shape automatically; a client-side concern added later (retry, logging a failed status code, a shared timeout) is then one edit in AuthorizedRequests.cs instead of hunting through 5 *ApiClient.cs files.
