# Match Profile's identity display to Login's identity box

Kategori: ux | Efor: S | Rank: 13

## Ne
In MainProject/UI/Pages/Profile.razor (.profile-identity-row, lines 13-18) and MainProject/UI/Pages/ProfileCss.razor (.profile-identity-row/.profile-identity, lines 32-47): Login.razor already wraps the same kind of data (the public identity string) in a .login-identity-box with background: AppColors.SurfaceSubtle.ToRgbaHex(true), border-radius: AppMeasures.Radius.Medium, and padding: AppMeasures.Space.Medium (LoginCss.razor lines 33-40). Profile's .profile-identity-row has none of that - verified in the current file it's bare flex layout with no background/padding, just text plus an IconButton floating directly on the aurora. Give .profile-identity-row (or a wrapping div) the same SurfaceSubtle box treatment as Login's box, and switch .profile-identity's font to a monospace stack so the long ML-DSA public key is easier to scan and compare character-by-character.

## Neden
Verified directly in both files: the same data (the public identity string) gets two different visual treatments on two adjacent pages in the same session - Login boxes it in a SurfaceSubtle card, Profile leaves it as naked text. It's a one-file-pattern-copy fix, not new design. The monospace addition has real functional value beyond consistency: this string is a cryptographic public key users are told to copy and share, and monospace makes look-alike characters (1/l/I, 0/O) distinguishable when scanning or comparing it, which a proportional font does not.
