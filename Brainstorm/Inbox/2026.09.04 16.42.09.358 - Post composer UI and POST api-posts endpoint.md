# Post composer UI and POST /api/posts endpoint

Kategori: feed | Efor: M | Rank: 11

## Ne
`IPostStore.CreatePostAsync` (MainProject/Backend/IPostStore.cs) and `LocalPostStore` (ChaySocialSonnet.Web/Backend/LocalPostStore.cs) are implemented and tested, and `GET /api/posts/recent` now exists (ChaySocialSonnet.Web/Backend/PostEndpoints.cs), but there is still no way to create a post: no `POST /api/posts` endpoint, no `PostApiClient.CreatePostAsync`, and no composer UI on Home.razor. Add the endpoint (using `AuthService.CurrentIdentity`/a signed request to identify the author — reuse the existing register/verify pattern's spirit rather than inventing a new auth scheme), the client method, and a small compose box (CoreInput + PrimaryButton) at the top of Home's Feed slot that calls it and prepends the new post to `_posts`.

## Neden
This is the natural next step after "PostCard + feed listing on Home": listing was verified with the empty state only, since there is currently no way to put a real post into the store through the running app at all. Without this, the feed feature stays half-built and PostCard's actual rendering (with real data) has never been exercised end-to-end in the browser.
