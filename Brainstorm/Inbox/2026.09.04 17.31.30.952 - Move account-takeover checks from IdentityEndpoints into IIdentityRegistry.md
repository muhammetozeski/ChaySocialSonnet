# Move account-takeover checks from IdentityEndpoints into IIdentityRegistry

Kategori: architecture | Efor: S | Rank: 13

## Ne
ChaySocialSonnet.Web/Backend/IdentityEndpoints.cs's /api/identity/register handler inline-checks `IdentityService.DerivePublicId(signingPublicKey) != request.PublicId` and the already-registered-with-a-different-key conflict before calling registry.RegisterAsync. Move both checks into LocalIdentityRegistry.RegisterAsync (ChaySocialSonnet.Web/Backend/LocalIdentityRegistry.cs, currently an unconditional `identities[publicId] = new(...)`) and change its return type on IIdentityRegistry (MainProject/Backend/IIdentityRegistry.cs) to report success/conflict/mismatch instead of bare Task. The endpoint lambda then just maps that result to BadRequest/Conflict/Ok.

## Neden
The two checks are the only account-takeover protection this system has, and today they exist solely as an inline minimal-API lambda with zero unit coverage — confirmed by grep: no test file references IdentityEndpoints at all, and LocalIdentityRegistryTests.cs never exercises a duplicate-registration or public-id-mismatch case. IIdentityRegistry.cs's own doc comment claims swapping in a Firebase-backed implementation later means registering a different IIdentityRegistry in DI, nothing else — that's false right now, since a new implementation would silently lose this protection unless someone remembers to copy the endpoint's inline logic. Putting the invariant in the registry makes it part of the contract every implementation must satisfy, and makes it unit-testable.
