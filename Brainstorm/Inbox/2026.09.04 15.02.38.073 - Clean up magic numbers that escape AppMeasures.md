# Clean up magic numbers that escape AppMeasures

Kategori: architecture | Efor: S | Rank: 9

## Ne
Bind the `PaddingX { get; set; } = 12` and `PaddingY { get; set; } = 6` defaults in MainProject/UI/Elements/Core/CoreChip.razor to AppMeasures.Space.Px12 / Px6. For the `.core-btn:active:not(:disabled) { transform: scale(0.95); }` in MainProject/UI/Elements/Core/CoreButtonCss.razor and the `.core-card.clickable:active { transform: scale(0.98); }` in MainProject/UI/Elements/Core/CoreCardCss.razor, add a new `Scale` class inside MainProject/UI/ThemeConstants/AppMeasures.cs (e.g. PressActive constants) and have both CSS files read from there.

## Neden
While AppMeasures.Space.Px12/Px6 are already defined, CoreChip re-writes them as literal 12/6 - violating the "single source" principle that the file's own comments emphasize (e.g. ScrollBottomInset reading from Size.BottomNavHeight). Also, while AppMeasures covers categories like Radius/Blur/Space/Size/Border/Duration/Opacity/ZLayer, the two different "pressed state" scale values (0.95 / 0.98) in two different files don't live in any constant - verified, there is no Scale category in the file.
