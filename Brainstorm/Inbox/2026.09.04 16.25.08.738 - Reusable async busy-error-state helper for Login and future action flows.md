# Reusable async busy/error-state helper for Login and future action flows

Kategori: architecture | Efor: S | Rank: 12

## Ne
Add a small reusable type (e.g. MainProject/UI/Architecture/AsyncOperationState.cs) exposing IsBusy, ErrorMessage, and RunAsync(Func<Task> work) that sets IsBusy=true, clears ErrorMessage, runs the work in try/catch (catching into ErrorMessage), and resets IsBusy=false in a finally. Replace Login.razor's hand-managed _isCreating/_isSigningIn/_errorMessage fields and HandleContinue's raw await chain with an instance of this helper.

## Neden
Verified in MainProject/UI/Pages/Login.razor: HandleContinue (lines 68-86) awaits ApiClient.RegisterAsync and ApiClient.SignInAsync with zero try/catch. If either throws (e.g. HttpRequestException when the server round-trip fails — a scenario made real by the just-shipped register/challenge/verify network flow), the exception propagates unhandled, _isSigningIn is never reset, and the Continue button is permanently disabled with no error shown and no retry path. A shared RunAsync helper fixes this defect once and gives every future async UI action (post composer, DM send) the same safe busy/error pattern instead of each page reinventing its own flags with the same missing-catch bug.
